2. What each API does

EndpointWho uses itWhat it doesCode path
POST /api/ships/scheduleOperatorPosition in. Model ETA, then a berth or a queue place, a requested arrival and, if useful, an advised speed.PortController.schedule → EtaService.predict → VesselVisitService.schedule → BerthService.allocate
GET /api/ships/berthsTerminalEach berth, whether occupied and by which vessel.PortController.berths → BerthService.status
PUT /api/ships/berths/{id}/releaseTerminalFrees a berth; the vessel is departed and the berth goes to the head of the queue.PortController.release → BerthService.release → handOver
POST /api/operator/etaOperatorAsks the model for an ETA. Stores nothing.VesselOperatorController.eta → EtaService.predict
POST /api/operator/vessels/{id}/acceptOperatorAccepts the requested arrival; it becomes the planned arrival. A stale time gets 409..accept → VesselVisitService.confirm
POST /api/operator/vessels/{id}/rejectOperatorDeclines with the time the vessel can make; answered with a new requested arrival..reject → VesselVisitService.replan → declareEta → BerthService.reschedule
POST /api/operator/vessels/{id}/omitOperatorSkips the call; its berth or queue place passes on..omit → VesselVisitService.omit → BerthService.cancel → handOver
GET /api/port-call/v2/eventsAny DCSA partyPublishes our timestamps in DCSA Port Call 2.0 format, with filters and paging.PortCallEventsController.events → PortCallEventPublisher.find
POST /api/port-call/v2/eventsCarrier systemReceives DCSA berth events: estimated, planned and actual arrival, actual departure, omitted call. Answers with feedback per event..receive → PortCallEventReceiver.receive → VesselVisitService
GET /api/agent/ping, POST /chat, POST /evaluateAnyoneGemini assistant. Its tools return fixed sample data, so answers do not reflect real berths.AgentController → HarborMasterAgentService → PortDispatchTools
GET /health, POST /predict (port 8000)The schedulerThe Python model service: rebuilds the training features and returns the ETA in minutes.src/predict_api.py → models/eta_xgb.pkl

3. The berth conversation, step by step

The four kinds of time: EST estimated (the ship or the model), REQ requested (the terminal), PLN planned (the ship's acceptance), ACT actual.

sequenceDiagram
  participant O as Vessel operator
  participant A as Scheduler (Spring Boot)
  participant M as ETA model (FastAPI)
  participant D as MySQL
  O->>A: POST /api/ships/schedule (position, speed, destination)
  A->>M: POST /predict
  M-->>A: ETA in minutes
  A->>D: vessel, vessel_visit, eta_prediction, EST event
  alt a berth is free
    A->>D: berth_allocation with planned end, REQ event (requested = ETA)
    A-->>O: BERTHED, berth, requestedArrival
  else port is full
    A->>D: REQ event (requested = when a berth is expected free)
    A-->>O: QUEUED, queue number, requestedArrival, advisedSpeedKnots
  end
  alt operator accepts
    O->>A: POST /api/operator/vessels/{id}/accept
    A->>D: pta_berth, PLN event
  else operator rejects
    O->>A: POST /api/operator/vessels/{id}/reject (time it can make)
    A->>D: new EST event, new REQ event, acceptance cleared
    A-->>O: new requestedArrival
  else operator omits the call
    O->>A: POST /api/operator/vessels/{id}/omit
    A->>D: visit CANCELLED, berth handed to queue head
  end
  O->>A: POST /api/port-call/v2/events (actual arrival)
  A->>D: ata_berth, visit BERTHED, allocation ACTIVE, ACT event
  O->>A: actual departure event, or terminal PUT release
  A->>D: allocation COMPLETED, visit DEPARTED, ACT event
  A->>D: berth allocated to the head of the queue, REQ event

4. The database

Things that exist (port, terminal, quay, berth, vessel), things that happen (vessel_visit, berth_allocation), and history that is only ever added to (eta_prediction, visit_event). A berth is occupied when it has an open allocation; there is no occupied flag.

6. Where the code lives

LayerFilesHolds
Python: datasrc/data_loader.py, src/feature_engineer.pyReads raw AIS, cleans sentinel values, cuts voyages, builds features and the minutes-to-arrival label.
Python: modelsrc/train.py, src/train_bigru.pyTrains XGBoost (in use) and the Bi-GRU experiment (not in use).
Python: servicesrc/predict_api.pyFastAPI /health and /predict.
Java: controllerscontroller/PortController, VesselOperatorController, AgentController, dcsa/PortCallEventsControllerThe HTTP endpoints in section 2.

Java: entitiesentity/topology (Port, Terminal, Quay, Berth), entity/vessel (Vessel), entity/visit (VesselVisit, BerthAllocation, EtaPrediction, VisitEvent and their enums)One class per table. Milestone and TimeClassifier carry the DCSA codes.
Java: repositoriesrepository/ Berth, BerthAllocation, Vessel, VesselVisit, EtaPrediction, VisitEvent, PortDatabase queries, including the locked "free berths" query and the waiting-queue query.
Java: request and response shapesmodel/ ScheduleRequest, ScheduleResponse, EtaRequest, EtaResponse, EtaEstimate, ConfirmRequest, RejectRequest, VisitDecisionThe JSON of our own endpoints.
Java: errorsexceptions/ GlobalExceptionHandler, BerthNotFound, VisitNotFound, VisitConflict404 and 409 responses.

Testssrc/test/, 8 classes, 54 testsMigrations, scheduling flow, planning rules, both controllers' JSON, DCSA publishing and receiving.
