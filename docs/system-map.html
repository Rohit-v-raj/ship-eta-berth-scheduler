1. The whole system

3. The berth conversation, step by step

The four kinds of time: EST estimated (the ship), REQ requested (the terminal), PLN planned (the ship's acceptance), ACT actual. The terminal sends times and never a speed; working out a speed is the operator's own sum. A berth is held from the terminal's answer, not from the ship's acceptance. After every change to the berth plan the terminal works out the waiting ships' times again and re-issues those that moved by 15 minutes or more.

sequenceDiagram
  participant O as Vessel operator
  participant A as Scheduler (Spring Boot)
  participant M as ETA model (FastAPI)
  participant D as MySQL
  participant P as Terminal planner
  O->>A: POST /api/operator/eta (position, speed)
  A->>M: POST /predict
  M-->>A: ETA in minutes
  A-->>O: estimated arrival (nothing stored)
  O->>A: POST /api/port-call/v2/events (EST arrival, with position)
  A->>D: vessel, vessel_visit, EST event, position
  alt a berth is free
    A->>D: berth_allocation with planned end, REQ event (requested = the estimate)
  else port is full
    A->>D: REQ event (requested = when a berth is expected free)
  end
  O->>A: GET /api/visits or GET /api/port-call/v2/events
  A-->>O: berth or queue place, requested arrival
  O->>A: POST /api/operator/eta (same position)
  A-->>O: the speed that meets the requested arrival
  alt operator accepts
    O->>A: POST /api/port-call/v2/events (PLN arrival = requested time)
    A->>D: pta_berth, PLN event
  else operator proposes another time
    O->>A: POST /api/port-call/v2/events (EST arrival: time it can make)
    A->>D: new EST event, new REQ event, acceptance cleared
  else operator omits the call
    O->>A: POST /api/port-call/v2/events (omitted port call)
    A->>D: visit CANCELLED by the vessel, berth handed to queue head
  else no answer within 60 minutes
    A-->>P: GET /api/visits shows the answer overdue
    P->>A: PUT /api/visits/{ref}/cancel (the planner's decision)
    A->>D: visit CANCELLED by the terminal, berth handed to queue head
  end
  O->>A: POST /api/port-call/v2/events (ACT arrival)
  A->>D: ata_berth, visit BERTHED, allocation ACTIVE, ACT event
  A->>D: planned end = arrival + stay, new REQ for waiting ships whose time moved
  O->>A: POST /api/port-call/v2/events (ACT departure), or planner PUT release
  A->>D: allocation COMPLETED, visit DEPARTED, ACT event
  A->>D: berth allocated to the head of the queue, REQ event

4. The database

Things that exist (port, terminal, quay, berth, vessel), things that happen (vessel_visit, berth_allocation), and history that is only ever added to (eta_prediction, visit_event). A berth is occupied when it has an open allocation; there is no occupied flag.

7. Progress

AreaStateNotes
ETA model and its serviceWorkingXGBoost, 69 min mean error on unseen vessels. Its label counts idle time near the berth as sailing, which makes it pessimistic close to port.
Persistence and data modelWorking10 tables, state survives a restart.
Berth and queueWorkingFirst free berth, a queue with a requested arrival for each ship, released berth goes to the queue head. Waiting ships' times are worked out again whenever the berth plan changes.
Berth fit and maintenanceWorkingA ship is given only a berth its length, beam and draft fit, and refused if it fits none. Maintenance windows are recorded in advance and planned around.
Late booked shipsWorkingA ship holding a berth that falls more than 4 hours behind its agreed time gives it up, if a waiting ship can be alongside sooner; it keeps its place in line.
Unanswered requestsWorkingA berth is held from the terminal's answer. A reply 60 minutes late is flagged on the planner's screen, and the planner can cancel the call. Nothing is cancelled automatically.
Operator's calculatorWorkingThe model's ETA for a position and the speed that meets the terminal's requested arrival. The terminal itself sends a time, never a speed.
Operator decisionsWorkingEstimate, accept, propose another time, omit, arrive, depart: all DCSA Port Call events, the one route into a call.
Console (React)WorkingPlanner and operator screens, event feed, wire inspector, stories. Seats instead of login.
DCSA Port Call 2.0WorkingPublishes and receives berth events. Not run through DCSA's conformance sandbox.
Queue reordering when a ship is lateMust solveThe queue never reorders, so a berth can stand empty for a delayed ship.
Time-driven replanningNot startedWaiting times follow events, not the clock: a berthed ship that overstays changes nothing until the next event.
ETA label fixNextEnd each training voyage when the ship stops, not when the crew sets "moored".
Type checks in allocationNot startedVessel type against terminal type; the data is in place.
OverstaysDeferredA planned end is a median stay, so half of all ships pass it. Needs a real departure time during the stay.
Service time by cargo amountNot startedStay depends on vessel type only; no reliable handling rates were found.
Assistant toolsStubReturns sample data.
Login and permissionsNot startedEvery endpoint is open. The console already has roles and one list of permissions, so login replaces its seat switcher.
